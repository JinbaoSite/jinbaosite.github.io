# TIGER：从商品语义编码到生成式召回

> 论文：[*Recommender Systems with Generative Retrieval*](https://arxiv.org/html/2305.05065v3)，Rajput 等，NeurIPS 2023。

在 [SASRec](https://dongjinbao.com/recsys/sasrec/) 中，用户历史和候选商品各有一个表示。模型根据历史得到用户当前的兴趣，再给候选商品打分。对于大规模召回，也可以先计算用户向量，再到商品向量索引里做近似最近邻搜索。

TIGER 把问题换了一种问法：**能不能让模型直接输出下一个商品的 ID？** 单纯把商品编号改成几个 Token 并不够。如果两件相似商品的编号完全随机，模型仍然要分别学习这两组符号。TIGER 先把商品内容压成一串有层次的离散编码，再让 Transformer 根据用户历史逐位预测这串编码。本篇拆开看两个问题：**为什么这种 ID 值得学习，以及论文如何验证它比随机编号更有用。**

## 1. 背景：把「给候选打分」改成「生成候选」

设用户历史为 $H=(i_1,\ldots,i_n)$。基于向量的召回通常计算用户向量 $u(H)$ 与商品向量 $v_i$ 的相似度，再找分数最高的一组候选。TIGER 则把每个商品映射为编码 $C(i)$，学习条件概率 $P(C(i)\mid H)$，从概率较高的编码中找回商品。

| 比较维度 | 向量召回 | TIGER |
| --- | --- | --- |
| 模型要预测什么 | 能和商品向量比较的用户表示 | 目标商品的 Semantic ID |
| 如何得到候选 | 在商品向量索引中做最近邻搜索 | 搜索高分编码，再用映射表找商品 |
| 推理成本主要由什么决定 | 向量维度、索引配置与检索预算 | 历史长度、编码长度、Beam 宽度与解码实现 |

变化不只在于输出格式。**向量召回的搜索空间是商品向量，TIGER 的搜索空间是编码前缀。** 如果两个商品共用前两个 Token，模型可以先预测共同前缀，再根据后续 Token 区分它们。不过，一条正确前缀如果在早期搜索时被剪掉，下面所有商品都无法在同一轮解码中找回来。

## 2. 模型架构

### 2.1 整体流程：先给商品编码，再学习用户序列

![商品内容向量经量化得到 Semantic ID](https://arxiv.org/html/2305.05065v3/semantic_id_generation_overview.png)

> [论文图 2(a)：商品内容向量量化与 Semantic ID 生成](https://arxiv.org/html/2305.05065v3#S3.F2.sf1)

两部分的训练目标不同。**RQ-VAE 学的是如何重建商品内容向量；推荐模型学的是下一次交互会发生在哪个商品上。** 论文先训练商品编码器，再用已经确定的编码训练序列模型。用户行为决定模型更愿意生成哪个编码，但不会在这一阶段反过来调整码本。

### 2.2 RQ-VAE：每一层只量化上一层留下的残差

![RQ-VAE 的逐层残差量化过程](https://arxiv.org/html/2305.05065v3/RQVAE_landscape_neurips.svg)

> [论文图 3：RQ-VAE 如何逐层逼近原向量](https://arxiv.org/html/2305.05065v3#S3.F3)

设 Sentence-T5 输出商品内容向量 $x$，RQ-VAE 的编码器把它映射为 $z=E(x)$。从 $r_0=z$ 开始，第 $d$ 层从自己的码本中挑出最接近当前残差的向量：

$$
c_d=\arg\min_j\|r_d-e_{d,j}\|_2^2,\qquad
r_{d+1}=r_d-e_{d,c_d}.
$$

这里 $e_{d,j}$ 是第 $d$ 层码本的第 $j$ 个向量，$c_d$ 是被选中的下标。第一层近似整个 $z$，后面的层不重复拟合 $z$，只补前面没解释完的部分。最终用选中向量的和近似原表示：

$$
\hat z=\sum_{d=0}^{D-1}e_{d,c_d},\qquad
\hat x=\mathrm{Decoder}(\hat z).
$$

例如，假设 $z=(2.3,0.8)$。第一层选中编号 7，对应 $(2.0,1.0)$，还剩 $(0.3,-0.2)$；第二层选中编号 1，对应 $(0.25,-0.25)$，只剩 $(0.05,0.05)$。两层输出的编码是 $(7,1)$，而不是两个连续向量本身。

训练时，重建误差让 $\hat x$ 保留原始内容信息；码本损失推动选中的码字贴近对应残差；承诺损失（commitment loss）让编码器输出向选定码字靠拢。**这些目标没有要求某个码字一定代表「护肤」或「洗发」。** 论文在 Beauty 数据上的可视化表明部分前缀呈现粗到细的分组，但不能把每个前缀直接当成一个人工定义的类目。

### 2.3 去碰撞：第四位是区分符，不是第四层量化

论文主实验把 768 维的商品内容向量投影到 32 维潜空间，使用 **三层残差量化，每层 256 个码字**。如果两个商品都得到 $(7,1,4)$，就分别追加后缀，得到 $(7,1,4,0)$ 和 $(7,1,4,1)$；没有冲突的商品也追加 0。

前三位是从内容向量学出来的，第四位让完整编码可以唯一映射回目录中的某件商品。相同的数字出现在不同位置也不是同一个 Token。论文给四个位置各分配 256 个符号，因此表示商品编码的词表有 $4\times256=1024$ 个 Token；这不包括用户 Token 和其他特殊符号。**词表不用为每个商品单独增加一个 Token，但商品映射表并没有消失。**

## 3. 生成式召回

### 3.1 训练：用户历史展开成编码序列

![TIGER 使用编码器和解码器预测下一件商品的 Semantic ID](https://arxiv.org/html/2305.05065v3/enc-dec-overview_neurips.svg)

> [论文图 2(b)：用于生成式召回的 Encoder–Decoder](https://arxiv.org/html/2305.05065v3#S3.F2.sf2)

假设用户最近交互过商品 A 和 B，下一次交互的是 C。编码器的输入是用户 Token 加上 A、B 各自的四位编码；解码器则预测 C 的四位编码。

论文用 T5X 实现 Encoder–Decoder，并把原始用户 ID 哈希到 2,000 个用户 Token。对四个商品编码位置而言，训练目标可以写成：

$$
\mathcal L_{\text{rec}}
=-\sum_{t=1}^{4}\log P(c_t\mid H,c_1,\ldots,c_{t-1}).
$$

也就是在已知用户历史和目标的正确前缀时，预测下一位 Token。训练时前缀可以直接从标签提供；推理时没有标签，模型只能沿自己已经选中的前缀继续生成。

### 3.2 推理：Beam Search 在前缀空间里保留多条路径

如果第一位最可能是 7，但以 7 开头的最佳完整编码不如另一条路径，只做逐位贪心就会错过它。Beam Search 每步保留多条累计分数较高的前缀，生成完成后再将编码映射回商品。

论文附录报告，三个数据集的 Top-10 预测中，无效编码占比约为 **0.1%–1.6%**，并讨论了扩大 Beam 后过滤无效结果的做法。[论文附录 E](https://arxiv.org/html/2305.05065v3#A5) 在 [PyTorch 复现](https://github.com/JinbaoSite/tiger-pytorch) 中，可以用目录里的合法编码构建 Trie，让解码器每一步只走合法分支。**这是复现中的解码约束，不是原论文主实验默认使用 Trie。** Trie 能避免走到不存在的商品编码，但不能保证有限宽度的 Beam 找到全局最优的 Top-K。

## 4. 实验：真正起作用的是「生成」，还是「怎么编码」？

### 4.1 主结果：头部排序的收益比扩大召回集合更明显

论文用 Amazon Reviews 的 Sports and Outdoors、Beauty、Toys and Games 三个子集预测下一次交互。每个用户的最后一条交互用于测试，倒数第二条用于验证，更早的交互用于训练。由于每个测试样本只有一个目标，Recall@K 看目标是否进入前 K，NDCG@K 还会对目标排得更靠后打折。下面只摘两个 K 值，便于看差异。[论文表 1](https://arxiv.org/html/2305.05065v3#S4.SS1)

| 数据集 | Recall@10：该指标最强基线 → TIGER | NDCG@5：该指标最强基线 → TIGER |
| --- | --- | --- |
| Sports and Outdoors | 0.0385 → **0.0400** | 0.0161 → **0.0181** |
| Beauty | 0.0647 → **0.0648** | 0.0249 → **0.0321** |
| Toys and Games | 0.0700 → **0.0712** | 0.0306 → **0.0371** |

Beauty 最有意思：NDCG@5 相对最强基线提升约 29%，但 Recall@10 只从 0.0647 到 0.0648，绝对差 **0.01 个百分点**。因此，更准确的说法是：**TIGER 在这组结果里的头部指标改善更明显，不能把它写成 Top-10 找回了大量额外目标。** 两列的最强基线也不总是同一个模型。

### 4.2 编码消融：换成随机 ID，生成模型还有效吗？

| Beauty 的编码方式 | Recall@10 | NDCG@10 |
| --- | ---: | ---: |
| 随机 ID | 0.0434 | 0.0250 |
| LSH Semantic ID | 0.0533 | 0.0309 |
| RQ-VAE Semantic ID | **0.0648** | **0.0384** |

[论文表 2](https://arxiv.org/html/2305.05065v3#S4.SS2) 比主表更直接地回答了这篇文章开头的问题。随机 ID 也能用同类生成框架预测，但效果低于带内容结构的编码；基于随机投影的 LSH 好于随机 ID，使用同类内容向量学习量化的 RQ-VAE 又进一步提升。**在这套实验里，生成框架不只是把编号拆成四位，编码里保留的结构本身也很重要。**

主结果仍然是公开数据上的离线比较。部分基线沿用了既有工作公开的结果；输入信息和训练设置也并非都在同一实验里逐项控制。表 1 说明整套方法在该评测下表现更好，不等于只换成自回归解码就能得到相同收益。

## 5. 工程取舍：新商品、目录和延迟

### 5.1 冷启动：新商品能编码，不代表会被模型直接生成

![Beauty 子集的冷启动召回对比](https://arxiv.org/html/2305.05065v3/NeurIPS/figures/cold_recall_K.png)

> [论文图 5(a)：固定新商品配额参数时，不同 K 下的冷启动召回表现](https://arxiv.org/html/2305.05065v3#S4.F5.sf1)

有标题、类目等内容时，新商品可以直接用训练好的 RQ-VAE 计算前三位编码。论文没有因此假设模型就会准确生成新商品的完整 ID，而是把模型预测出的**前三位**作为查找键，从同前缀的新商品中扩展候选，并用一个参数限制新商品在 Top-K 中所占的比例。这是「生成已有路径，再扩展同组新商品」，不是模型已经学会了新商品的交互概率。

论文还提高解码温度，观察 Beauty 的 Top-K 类目熵。从温度 1.0 到 2.0，Entropy@10 从 0.76 到 1.38。它说明采样可以改变类目分布，不说明准确率、用户满意度或长期指标也会提高。[论文 §4.3](https://arxiv.org/html/2305.05065v3#S4.SS3)

### 5.2 省掉商品向量 ANN，不等于省掉召回成本

历史里有 $n$ 件商品，四位 Semantic ID 会把它们展开为约 $4n$ 个商品 Token。词表较小的好处，要和更长的输入、自回归解码及 Beam Search 的成本一起看。目录也需要维护完整 ID 到商品的映射；如果更换码本，同一个商品的编码可能改变，模型、目录映射和约束解码所用的 Trie 就必须使用兼容版本。

所以工程上更值得测的是：**在相同的候选预算下，Recall@K、无效编码率、尾延迟和资源开销怎么一起变化。** 论文的离线排序结果不能直接替代这组部署指标。

## 6. 总结

TIGER 把生成式召回拆成两件事：先用残差量化构造可以共享前缀的商品编码，再根据用户行为生成目标编码。主实验说明这套组合在三个数据集上有竞争力；随机 ID 消融进一步说明，**不是能生成 ID 就够了，ID 之间有什么结构也决定了模型能学到什么。**

还有一个自然的后续问题：**商品内容相似，不一定意味着用户会用相似的方式点击或购买。能不能把协同信号直接放进编码器？** 这正是下一篇 [LETTER](https://arxiv.org/abs/2405.07314) 要拆的问题。
